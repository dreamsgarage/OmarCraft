## The fix

- Every check runs `checkupdates` (pacman-contrib), as Omarchy's own update check does, with
  `CHECKUPDATES_DB` pointing to a private copy in `~/.cache/omarchy/omarcraft/checkup-db`: it refreshes
  that copy of the package lists without root and without touching the system's. The catalog's packages
  are then read from the copy (`pacman -Si --dbpath`) into `repo-latest.tsv`, versions checked like any
  network input. A failed check keeps the previous answer.
- An installed tool a repo ships is compared with the newer of the system's lists and that copy: `↑ system`
  when its repo has a newer build, and Omarchy's update, which refreshes the lists before it upgrades,
  brings exactly that build. A tool not yet installed still offers what an install brings now.
- *Update all* updates every pending app: AUR apps alone one package each through the AUR helper, as
  before; once an app from a package repo is among them, Omarchy's update, which brings them all at once
  (its AUR step included), with a confirmation naming each app and version. Same for the menu entry and
  `omarcraft update` without ids.
- The list is fetched at every six-hourly check (`CATALOG_MAX_AGE_MINUTES` 360).
- Cache format 4, so the first read after the update checks at once.
- README: the apps' own update prompts.

Measured on the author's machine against the real system and the live repos: the full check (catalog,
AUR, repos) 6.1 s in the background, the copy 8.8 MB, the panel's read 0.11 s; WordCraft 0.15.2 to
0.16.0 and GridCraft 0.16.1 to 0.17.0 shown as system updates; the system's own lists untouched.

## Tests

249 offline tests (15 new): the author's case (stale lists, a newer build in Omarchy's repo), the badge
leading to Omarchy's update and clearing after it, an install offering what it brings, a failed repo
check (the copy left broken) keeping the last answer, a malformed version in the copy, and the six-hour
cadence. Each new piece was broken on purpose in a copy (seven breaks), and a test failed each time. The
first try missed one: the fake kept its old copy on failure, so a failed check that overwrote the answer
looked unchanged; the fake now leaves the copy broken, as a failed refresh can.
