# OmarCraft 0.5 plan

**Status: proposed 2026-10-18.** Built on the local branch `v0.5`; nothing is pushed while the 0.2.0
marketplace submission (omacom/omarchy-plugin-marketplace#12089) is open, because `main` is frozen at the
validated commit. Testing happens on the author's machine by pointing the installed plugin at the branch.

## Goal

Three more tools beyond ArtCraft, chosen by benchmark (see *Benchmark* below): **Typesetter** (Typst
writing), **KolourPaint** (quick paint, screenshot edits) and **Vikunja** (tasks, with its own local
server). Same panel, same keys, same "nothing is compiled" promise. 17 tools in all.

## Decisions (the author, 2026-10-18)

| # | Decision |
|---|---|
| 1 | Vikunja ships as **client + local server**: OmarCraft runs the server under the user, on demand. |
| 2 | Typesetter and KolourPaint come from Arch's **official repos**. Their update badge reads `↑ system update` and opens Omarchy's system update; *Update all* keeps updating the AUR apps only. |
| 3 | Groups: Typesetter → **Office**, KolourPaint → **Creative**, Vikunja → **Notes**, renamed **Notes & tasks** (key `n` unchanged). No new chips. |
| 4 | No canvas round: the author reviews the real panel on the branch. |
| 5 | Qualification rule: stable desktop release; prebuilt (official repo or AUR `-bin`); maintained, **open-source** licence; memory budget **~150 MiB idle in one native process**, with documented exceptions for tools that add a capability ArtCraft lacks. Exceptions today: Memospot, Vikunja. |

The 150 MiB figure and "open-source" (needed by GPL Typesetter and KolourPaint, AGPL Vikunja) were proposed
and are adopted with this plan unless the author says otherwise.

## Design

### 1. A package kind per tool

Today every app is `<id>-bin` from the AUR. The catalog gains two fields for tools beyond ArtCraft:

| id | kind | packages | desktop id |
|---|---|---|---|
| memospot | aur | memospot-bin | memospot |
| typesetter | repo | typesetter | net.trowell.typesetter |
| kolourpaint | repo | kolourpaint | org.kde.kolourpaint |
| vikunja | aur | vikunja-desktop-bin vikunja-bin | vikunja-desktop |

ArtCraft rows stay implicit (`aur`, `<id>-bin`, `ai.storyteller.<id>`).

| Action | `aur` | `repo` |
|---|---|---|
| Latest version | AUR RPC (as today) | the local sync database (`pacman -Si`), no network |
| Install | `omarchy-pkg-aur-add` | `omarchy-pkg-add` |
| Update one / *Update all* | `yay -S <pkgs>` | not offered: badge `↑ system update` opens `omarchy-update` in the floating terminal |
| Remove | `omarchy-pkg-drop` | `omarchy-pkg-drop` |

A `repo` tool is "update ready" when the sync database has a newer version than the installed one, which
means the system has not been updated since the last `pacman -Sy`.

### 2. Vikunja's local server

- **On demand, not a service.** `omarcraft launch vikunja` starts `/usr/bin/vikunja` (from `vikunja-bin`)
  under the user if it is not running, waits for its health check, then opens the desktop client. When the
  client process exits (Quit from its tray menu; closing the window only hides it to the tray), the server
  is stopped. Nothing runs while Vikunja is closed, so the idle cost when not in use is 0.
- **Data and config:** `~/.local/share/omarcraft/vikunja/` (SQLite database, files, `config.yml` written
  once by OmarCraft: listen `127.0.0.1:3456`, public URL `http://127.0.0.1:3456/`, a generated JWT secret,
  registration on). Kept when Vikunja is removed, like every app's documents.
- **The package's system service is not used.** `vikunja-bin` ships a disabled system unit and a `vikunja`
  system user; OmarCraft never enables it and never uses sudo.
- **Launching outside the panel** (app launcher, Walker): at install OmarCraft writes a user desktop entry
  `~/.local/share/applications/vikunja-desktop.desktop` whose Exec goes through `omarcraft launch vikunja`
  and falls back to the plain client if OmarCraft is gone. Removed again with Vikunja.
- **First run:** the client asks for a server once; a notification says to enter `http://127.0.0.1:3456`
  and register a local account. The client remembers both.
- **Port taken:** if 3456 is in use by something else, launch stops with a notification naming the port.

### 3. Panel

- 17 tiles; hero `N OF 17 INSTALLED`; chip `n Notes & tasks · N`.
- New badge state for repo tools: `↑ system update` (same position and colour as the AUR `↑ x.y.z` badge);
  rows layout says `Update with the system · ⏎`.
- Vikunja's tile carries a small server dot while its server runs (hover: `server on 127.0.0.1:3456`).
- Everything else unchanged.

### 4. README and docs

- *Beyond ArtCraft* gets the new rule (decision 5) and a table with the exceptions column.
- `docs/v1-acceptance.md` gains rows 23–30 (below). `docs/Testing.md` gets the branch-testing recipe.
- Manifest 0.5.0, CHANGELOG entry.

## Phases

1. **Package kinds**: catalog fields, version lookup for `repo`, install/update/remove routing, `list` and
   `state` output; offline tests with fixtures for both kinds. (CLI only, no UI change yet.)
2. **Vikunja server**: `serve`/`stop` helpers, config writer, on-demand launch wrapper, desktop override on
   install/remove, port check; tests with a stub `vikunja` binary.
3. **Panel**: the `system update` badge, the server dot, the renamed chip, 17-tile layout check.
4. **Docs**: README rule, acceptance rows, Testing recipe, CHANGELOG, manifest 0.5.0.
5. **Local scanner run** (`tests/marketplace-baseline.mjs`): expect new evidence (a spawned local server,
   a written desktop entry); record it before any release.
6. **Author testing** on the branch (acceptance rows below).

Tag and release only after #12089 is resolved; then the change goes through the marketplace verification
form with the new commit SHA.

## Risks

- **Scanner outcome** may move beyond "package-manager only" (local server process, desktop entry). Known
  before release from phase 5.
- **`vikunja-desktop-bin`** has 0 votes and one bulk maintainer; `vikunja-bin` has 2 votes. If either
  stalls, the tile shows the AUR version it has.
- **Electron 43** comes from the official repos as a dependency (~300 MB on disk) on machines without it.
- **Official-repo lag**: Typesetter in extra trails upstream by a release (0.15.2 vs 0.16).
