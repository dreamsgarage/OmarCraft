# OmarCraft 0.5.4 plan

**Status: decided 2026-11-07 (the author: follow A; both sources are compliant with Omarchy, and the
launcher must work smoothly whichever one installed an app). Built on the branch `v0.5.4-dev`; not
released.** `main` is at 0.5.3 (57969bd), which this release replaces.

## The problem

WordCraft and GridCraft would not update from the panel, on two machines.

- **Cause.** Omarchy's own package repo (`[omarchy]`, first in `pacman.conf`) started shipping
  `wordcraft-bin` and `gridcraft-bin` in 2026-11, under the same names as the AUR packages, built and
  signed by Omarchy. pacman and the AUR helper both take a package from a repo when one ships it, so 0.5.2's
  package-exact update reinstalled Omarchy's build each time and the badge stayed. `pacman.log`,
  2026-11-06 15:05: `reinstalled gridcraft-bin (0.16.0-1)`, `downgraded wordcraft-bin (0.15.1-1 -> 0.15.0-1)`.
  Omarchy's builds trail the AUR's: on 2026-11-07, 0.16.1 against 0.17.0 (GridCraft) and 0.15.2 against
  0.16.0 (WordCraft).
- **0.5.3** (2026-11-07, pushed to `main` without a tag) set out to treat installed packages that are not
  foreign as repo packages. It read `pacman -Qm` (`name version` lines) as names, so no package was ever
  foreign and every installed tool became a repo tool. A check then asked the AUR about nothing: with every
  tool installed it failed, and the panel said `OFFLINE · Could not reach the AUR` while online, the list
  frozen at the last AUR versions; with one tool missing, it erased the AUR version of every installed app.
  The badges read `↑ system` and opened Omarchy's update, which cannot bring an AUR build, so WordCraft and
  GridCraft kept a badge no update could clear (the author's second machine, 16 of 16 installed).
  `check` and `list` took 8 s (28 `pacman -Qm` runs). Its tests passed (169) because the fake `pacman`
  printed `-Qm` without versions.

## Options (2026-11-07)

| | A: follow the repo when one ships the app | B: always the AUR build |
|---|---|---|
| How | The repo's build: `omarchy-pkg-add`, updates with the system | `yay -S aur/<pkg>` for installs and updates |
| Newest build | The repo's, which can trail the AUR's by a day or so | The AUR's, at once |
| Over time | One source per app; pacman and the AUR helper agree with the panel | Omarchy's update swaps in the repo's build whenever it is newer; the AUR helper's own update never touches a name a repo ships; the panel has to track the source |
| Packages | Signed by Omarchy | Built from the AUR packager's PKGBUILD |

**Decision: A**, with the author's requirement that the launcher works smoothly whichever source installed
an app, both being compliant with Omarchy.

## Design

1. **Kind.** A tool whose package a configured repo ships is a repo tool, installed or not and whatever
   installed it; any other is an AUR tool. Read from the local sync databases with one `pacman -Si` naming
   every catalog package (no network), `LC_ALL=C` because pacman translates its field names; the first
   repo that ships a name wins, as in pacman. Typesetter and Planify stay pinned to the repos.
2. **Cache.** That answer is kept in `~/.cache/omarchy/omarcraft/sync.tsv` under a stamp of `pacman.conf`,
   the sync databases and the catalog's package list, and asked again only when the stamp changes (after a
   sync). A failed read is not kept.
3. **Versions.** The catalog's version column holds the AUR's version of every tool not pinned to a repo
   (format 2). A repo tool shows and is compared with the repo's version, never the AUR's: a badge appears
   only when its action can deliver that version. An AUR tool keeps the AUR's version, so a tool a repo
   stops shipping goes back to the AUR with its AUR version at hand, without waiting for a check.
4. **Checks.** A check fails only when the AUR does not answer, or answers with an error.
5. **Upgrade.** A cache without the format marker is refreshed once, at once, and the old failure's
   retry wait is dropped.
6. **Panel.** No new UI. The state carries `repo`; the subtext of a repo tool not yet installed names it
   ("from Omarchy's repo", "from the Arch repos", or "from the <name> repo"), where 0.5.3 said "from the
   Arch repos" for every repo.

## How each case behaves

| Case | Panel | Action |
|---|---|---|
| Omarchy's build installed, AUR ahead | Repo's version, no badge | None needed; Omarchy's update brings the repo's next build |
| Omarchy's repo has a newer build than the installed one | `↑ system` | Omarchy's update; the badge clears |
| AUR build installed, a repo ships the name, AUR build newer | Repo tool, no badge | Nothing reinstalled or downgraded; the repo's build arrives once it is newer |
| AUR build installed, a repo ships a newer one | `↑ system` | Omarchy's update brings the repo's build |
| Not installed, a repo ships it | Repo's version, "from Omarchy's repo" | `omarchy-pkg-add`; no badge after the install |
| A repo stops shipping an installed app | AUR app again, AUR's version | Package-exact AUR update |
| A repo starts shipping an app | Repo app after that sync | As above |
| Source build, a repo ships the `-bin` | Source build | Never updated or removed by OmarCraft |
| AUR app, no repo ships it | AUR's version, `↑ x.y` | Package-exact AUR update, as before |

## Measured (2026-11-07, the author's machine, real package databases and the live AUR)

All sixteen tools installed: online; twelve AUR apps compared with the AUR, WordCraft and GridCraft with
`[omarchy]`, Typesetter and Planify with `[extra]`; no badge. Panel read 0.12 s with one package query
(0.41 s once after a sync, one more for the repos), `check` 0.45 s, `list` 0.47 s (0.5.3: 0.41 s, 7.9 s,
7.9 s). Marketplace baseline unchanged from 0.5.2: review-required, package-manager only, no findings.
Offline tests: 216; each fix was checked by breaking it on purpose in a copy (eight breaks, among them
0.5.3's own rule, each caught).
