OmarCraft

Productivity tools from the Omarchy bar: the ArtCraft Craft apps and more — behind one bar icon, in a native panel that shows what is installed, what is not, what has a newer build, and one action per tool to launch, install, update or remove.

01Beyond ArtCraft

Every tool is a prebuilt package — a -bin from the AUR or a package from the Arch repos, installed through Omarchy's own package commands — so pacman owns it and nothing is ever compiled. A tool earns a tile when it:

  1. has a stable desktop release (tagged, not a release candidate or source-only build),
  2. ships prebuilt, in the Arch repos or as an AUR <id>-bin, with a desktop entry,
  3. comes from a maintained upstream under an open-source licence,
  4. stays near 150 MiB idle in one native process, like the Craft apps (70–90 MiB measured),
  5. does something an office, design or creative user wants on the desktop.

A tool that adds a capability ArtCraft lacks may exceed item 4; its row says so. Today's three:

Tools from the Arch repos update with the system: their badge reads ↑ system and opens Omarchy's update, because updating one repo package on its own is a partial upgrade.

Vikunja (0.5.0 only)

OmarCraft 0.5.0 carried Vikunja and 0.5.1 dropped it: its desktop app signs in only through the browser, and on a stock Omarchy that hand-off kept failing. If you installed it with 0.5.0, OmarCraft deletes the desktop entry it wrote for it and tells you once. Your Vikunja data stays in ~/.local/share/omarcraft/vikunja; the app is removed like any package, with omarchy pkg drop vikunja-desktop-bin vikunja-bin.

02The panel

Left-click the bar icon (or Tab from a neighbouring panel). Two layouts, switched live with t:

  • Tiles (default): three apps per line, each tile the app's glyph in its own ArtCraft colour over its name. Installed tiles have a tinted fill, available ones only an outline.
  • Rows: one app per line with a caption (0.7.0-1, Update ready 0.7.0 → 0.8.0, Install 0.9.0 · prebuilt, no compiling) and one action at the right edge.

What the panel shows

  • Hero. The rocket logo, then the one-line situation: 4 OF 16 INSTALLED · 2 UPDATES, INSTALLING WORDCRAFT…, OFFLINE · CACHED LIST, LAST JOB FAILED. The arrow at the right checks the AUR now.
  • UPDATES · N. Apps with newer builds, each with an ↑ 0.8.0 badge next to Update all.
  • INSTALLED · N. Your apps that are up to date; Enter launches, or focuses an open window.
  • AVAILABLE · N. The rest. Enter opens a one-line confirm; a terminal opens and asks for your password.
  • Group chips, each with its key: c Creative, o Office (WordCraft, DeckCraft, GridCraft, PdfCraft, Typesetter), n Notes (Memospot, Planify) — counting the apps you don't have.
  • Remove. Right-click a tile or press x: one terminal runs Omarchy's package drop; your files stay.

03Updates

Every six hours, and whenever you press r or right-click the icon, OmarCraft compares your installed -bin packages with the AUR. Newer builds show on the tiles and the icon; the six-hourly check sends one desktop notification per new set. If the AUR cannot be reached the hero says OFFLINE · CACHED LIST and the panel retries every ten minutes. Updates are package-exact and run through the AUR helper Omarchy ships, in a floating terminal that asks for your password. omarchy update updates them too.

04Command line and IPC

Everything the panel does is a subcommand of one script, usable from scripts and keybindings:

P=~/.config/omarchy/plugins/omarcraft.productivity/bin/omarcraft
$P state                      # the JSON the panel reads (local files only)
$P list                       # catalog with install state
$P launch <id>                # e.g. photocraft
$P install <id>...            # floating terminal, one run
$P install-group all|creative|office|notes
$P remove <id>...             # Omarchy's pkg drop; your files stay
$P update [id...]             # named apps, or every app with a newer build
$P check [--notify]           # pending updates; exit 0 if any
$P refresh [-f]               # fetch catalog and AUR versions now
omarchy-shell omarcraft.productivity open | close | toggle | refresh
omarchy-shell omarcraft.productivity launch <id>
omarchy-shell omarcraft.productivity install "<id> <id>"   # no confirm: a script is explicit
omarchy-shell omarcraft.productivity layout tiles|rows

An ArtCraft section in the Omarchy menu is opt-in and reversible: $P setup-menu / $P remove-menu. It writes one marked block into omarchy-menu.jsonc and nothing else.

05Install, upgrade & remove

Requires Omarchy 4 (Quattro) — no Python or extra packages.

omarchy plugin add https://github.com/dreamsgarage/OmarCraft.git --enable

The rocket icon lands in the right section of the bar. Enabling installs no app and writes no configuration; nothing happens until you pick something in the panel.

Upgrade from an earlier version

From any earlier version, update the plugin and answer yes when it asks, then restart the shell so the panel loads the new code. Your installed apps are not touched and nothing new is installed.

omarchy plugin update omarcraft.productivity
omarchy restart shell

The panel header then reads N OF 16 INSTALLED, and this prints 0.5.2:

jq -r .version ~/.config/omarchy/plugins/omarcraft.productivity/manifest.json

If the update says cannot fast-forward or not a git checkout, reinstall instead: omarchy plugin remove omarcraft.productivity, then the omarchy plugin add line above. Your apps stay installed.

Remove

To remove the plugin:

omarchy plugin remove omarcraft.productivity

Apps stay installed; remove them from the panel first if you want, or like any package (omarchy pkg drop photocraft-bin).

06Safety

  • Only catalog apps reach a package command, by an id checked against a strict pattern; each maps to its AUR <id>-bin or, for a tool from the Arch repos, a fixed package name (typesetter). The plugin does not use sudo or pkexec; installs, updates and removals all run through Omarchy's own commands in a visible terminal that asks for your password, and a job cut short is reported as interrupted.
  • Network use is the app catalog from raw.githubusercontent.com and versions from the AUR RPC, every 24 hours, with bounded timeouts (Arch repo versions come from the local sync database); a failed check keeps the old list and says OFFLINE, never "up to date". The panel itself never waits on the network.
  • Files stay under ~/.cache/omarchy/omarcraft/ and ~/.local/state/omarchy/omarcraft/. Nothing under ~/.config without the opt-in commands. Where 0.5.0 installed Vikunja, 0.5.1 deletes, once, the desktop entry and launcher 0.5.0 wrote for it.

07How it works

PathRole
manifest.jsonkinds: ["bar-widget"], entry point Panel.qml, default section right
Panel.qmlBar icon, KeyboardPanel, both layouts, cursor, confirm, keys, IPC
Service.qmlRuns bin/omarcraft state, watches job.json, six-hourly check
Model.jsPure helpers: sections, meta line, subtexts, confirm text
bin/omarcraftCatalog, installed state, jobs, launch, the opt-in menu section
tests/bash tests/run.sh: offline, every external command stubbed

A job is one floating Omarchy terminal running bin/omarcraft job install …: it calls the Omarchy command, records the result and pokes the panel. The panel never claims success from an exit code — it re-reads the package database.
