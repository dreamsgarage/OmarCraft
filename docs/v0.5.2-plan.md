# OmarCraft 0.5.2 plan

**Status: proposed 2026-10-23 (the author: "add a kanban app under Notes, with Memospot").** Built on the
local branch `v0.5.2-dev`. `main` stays at v0.5.1 while its marketplace verification
(omacom/omarchy-plugin-marketplace#12738) is open; testing happens on the author's machine by pointing the
installed plugin at the branch (`docs/Testing.md`).

## Goal

Kanban boards in *Notes*, next to Memospot, without a server or a sign-in: what Vikunja set out to do in
0.5.0 and could not deliver. Sixteen tools.

**Packaging fault (blocks release).** `kanri-bin` declares `libsoup`, the old 2.x library. Arch's repos
no longer carry it; only the AUR source package `libsoup` 2.74.3 provides it, so installing `kanri-bin`
makes the AUR helper compile libsoup with meson, against OmarCraft's "nothing is ever compiled". Kanri
never loads it: the binary links `libsoup-3.0.so.0` (from `libsoup3`, which `webkit2gtk-4.1` already
requires), and every library it needs is already on a stock Omarchy. The fix is one line in the
package's `depends`: drop `libsoup`, or replace it with `libsoup3`. Proposed comment for
https://aur.archlinux.org/packages/kanri-bin:

> Thanks for packaging Kanri! `depends` lists `libsoup`, but the binary links `libsoup-3.0.so.0`
> (`readelf -d /usr/lib/kanri | grep soup`), which comes from `libsoup3`. libsoup 2 is no longer in the
> Arch repos, so `libsoup` now resolves to the AUR source package and installing kanri-bin compiles an
> unused library. Could you replace `libsoup` with `libsoup3` (or drop it, since webkit2gtk-4.1 already
> depends on libsoup3)?

## Risks

- Kanri's releases are slow (one in the last twelve months); a broken release would wait upstream.
- The AUR package has one maintainer and five votes; if the fix does not come, Kanri waits or OmarCraft
  looks for another packaging.
