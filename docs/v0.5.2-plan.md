## Considered first: Kanri

Kanri (kanriapp/kanri) was the author's first pick on 2026-10-23 and was built on this branch. It was
replaced because its AUR package could not be installed without compiling, which depends on its packager:

### Kanri against the qualification rule (2026-10-23)

| # | Rule | Kanri | Result |
|---|---|---|---|
| 1 | Stable desktop release | 0.8.2, tagged 2025-09-24, not a release candidate. Upstream commits continue (last 2026-10-17) | pass; releases are slow |
| 2 | Prebuilt, with a desktop entry | AUR `kanri-bin` 0.8.2-1 repackages the official `.deb`, pinned by SHA-256 (checked). Entry `kanri.desktop`, window class `kanri` on native Wayland | pass, **with a packaging fault** (below) |
| 3 | Maintained open-source upstream | kanriapp/kanri, GPL-3.0, 2,068 stars, 177 forks | pass |
| 4 | Near 150 MiB in one native process | 308 MiB in 3 processes at 45 s (Tauri on WebKitGTK), measured from the release binary with a throwaway home | exception, like Memospot (371 MiB, 4 processes): it adds kanban boards, which ArtCraft lacks |
| 5 | Useful to office, design and creative users | Boards, columns and cards for planning work, offline | pass |

**Packaging fault.** `kanri-bin` declares `libsoup`, the old 2.x library. Arch's repos
no longer carry it; only the AUR source package `libsoup` 2.74.3 provides it, so installing `kanri-bin`
makes the AUR helper compile libsoup with meson, against OmarCraft's "nothing is ever compiled". Kanri
never loads it: the binary links `libsoup-3.0.so.0` (from `libsoup3`, which `webkit2gtk-4.1` already
requires), and every library it needs is already on a stock Omarchy. The fix is one line in the
package's `depends`: drop `libsoup`, or replace it with `libsoup3`. Proposed comment for
https://aur.archlinux.org/packages/kanri-bin:

> Thanks for packaging Kanri! `depends` lists `libsoup`, but the binary links `libsoup-3.0.so.0`
> (`readelf -d /usr/lib/kanri | grep soup`), which comes from `libsoup3`. libsoup 2 is no longer in the
> Arch repos, so `libsoup` now resolves to the AUR source package and installing kanri-bin compiles an
> unused library. Could you replace `libsoup` with `libsoup3` (or drop it, since webkit2gtk-4.1 already
> depends on libsoup3)?

## Decisions

| # | Decision |
|---|---|
| 1 | Planify joins *Notes* (chip `n`) with Memospot; the menu's *Install Notes* names both. |
| 2 | A repo tool like Typesetter: package `planify`, installed with `omarchy-pkg-add`, version from the sync database, updated with the system (badge `↑ system`); desktop id `io.github.alainm23.planify`. |
| 3 | Tile colour from its icon, `#3571e4`; ink `#2968e0` on light (5.1:1 on white) and `#7aa8ff` on dark (7.2:1). Glyph `nf-md-view_week` (U+F0576), three columns. |
| 4 | A guard (added 2026-10-24, after Kanri's tile started compiling libsoup twice on the author's machine): before an AUR install or update, every declared dependency must be installed or in the Arch repos, or the job stops before the AUR helper runs. Checked live: `kanri-bin` refused for `libsoup`, all fourteen other AUR tools pass. |
| 5 | A failed job is acknowledged when the panel that showed it closes, instead of staying flagged until another job succeeds. |
| 6 | **Working with others is a foundation of the rule** (the author, 2026-10-24): every tool beyond ArtCraft must let its work be shared and taken elsewhere, through an open format or a sync or sharing service the user chooses, with a way to export. README *Beyond ArtCraft* gains item 6 and a *Working with others* table. |

## Risks

- Planify pulls in Evolution's data server (contacts and calendar plumbing). It is all from the Arch repos,
  but it is the heaviest dependency set of any tool; the footprint above is what users should expect.
- Planify is a task manager first: the board is a per-project view, not the whole app.
