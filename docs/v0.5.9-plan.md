# OmarCraft 0.5.9 plan

**Status: prepared 2026-11-15 on the branch `v0.5.9-dev`, not released.** The author keeps 0.5.8 for now
(2026-11-15: "keep it as a branch we will live with 0.5.8 for now"). `main` stays at 0.5.8, the
marketplace's verified commit (5170074).

## Why

The places users look don't explain how to update an installed copy, and the real fix is Omarchy's
(the author, 2026-11-15: "it must be fixed by omacom - omarchy"):

- After `omarchy plugin update`, the running shell keeps the old panel until `omarchy restart shell`.
  Its reload calls `Qt.clearComponentCache()` only if that is a function, and in Quickshell 0.3.2 it is
  not (omacom/omarchy#17854, with a 👍 and a comment from the author).
- The marketplace page shows only the install command (omacom/omarchy-plugin-marketplace#15054).
  Running it again on an installed copy fails with a message that never mentions `omarchy plugin
  update` (omacom/omarchy#18993).
- The manual's plugins chapter leaves the restart out (omacom/omarchy discussion #18992).

On 2026-11-15 the author's own machine still showed 0.5.6, four days after 0.5.8. `omarchy plugin add`
had refused, and after the update the shell kept the old panel until a restart.

The marketplace listing has no notes field. The maintainer notes of the submission
(omacom/omarchy-plugin-marketplace#12089) are not published, and the only text the page takes from the
plugin is `manifest.json`'s `description`.

## The change

One sentence at the end of the description, so the marketplace page shows the steps:

> Update: omarchy plugin update omarcraft.productivity, then omarchy restart shell (until
> omacom/omarchy#17854 is fixed); if it refuses, see the README.

The description grows from 355 to 506 characters, and the version becomes 0.5.9. The README already
has both paths: update then restart, and remove then add when the update refuses (`README.md`, "To
upgrade"). It does not change. Nothing else changes either: not the panel, the scripts or the cache.

The sentence is a stopgap. It comes out again in the first release after Omarchy ships the fix for
#17854.
