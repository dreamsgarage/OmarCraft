## Why the AUR

The AUR `-bin` packages download ArtCraft's own release files (`url=https://github.com/storytold/wordcraft`,
`source=$url/releases/download/v$pkgver/…`), so "from ArtCraft" through the package manager means the AUR
build. Installing ArtCraft's files outside pacman is not an option: OmarCraft only installs packages
(marketplace review, 0.5.5: "package helpers or package-specific yay"). The AUR trailed ArtCraft by about
5½ hours on 0.17.0. Omarchy's repo had not followed about 8 hours after the release.

## The decision (A) and what it reverses

0.5.4 weighed the same two options (its "B: always the AUR build") and chose to follow the repo. 0.5.7
takes the AUR again for the Craft apps, knowing the costs 0.5.4 listed. This plan answers each one:

| 0.5.4's concern | Answer in 0.5.7 |
|---|---|
| pacman and the AUR helper take a name from a repo when one ships it (2026-11-06: a plain `yay -S wordcraft-bin` *downgraded* the AUR build to Omarchy's) | Every install and update of such an app names the AUR explicitly: `yay -S aur/<pkg>`. Tests fail if any path omits the prefix |
| The AUR helper's own update (`yay -Sua`, inside Omarchy's update) never touches a name a repo ships | OmarCraft updates these apps itself, one package at a time, as it does every AUR app |
| Omarchy's update installs the repo's build whenever it is newer | Accepted: the machine then has the newer of the two builds, which is never a downgrade. pacman's `-Syu` keeps a newer local build ("local is newer"), so an AUR build ahead of Omarchy's stays |
| The panel has to track the source | The panel compares the installed version with the AUR's. Which packager built it does not matter, because both builds carry the same name and files |

## Omarchy's 24-hour hold (found 2026-11-09, after the build)

Omarchy's repo is a day behind by design: `pkgbuilds/wordcraft-bin/.omarchy/package.json` and
`gridcraft-bin`'s set `"min_release_age": "24h"`, `"auto_merge": true` (checked hourly) and
`"release_ring": "fast"` (straight to stable). omarchy-pkgs `docs/upstream-sources.md`: the hold exists
"to quarantine fresh releases until maintainers have had time to pull a bad or compromised one". Measured:
GridCraft 0.17.0 released 2026-11-06 20:21 UTC, merged into Omarchy's repo 2026-11-07 20:36 UTC. The AUR
has no such hold. #2390 was corrected the same day (its third suggestion withdrawn).

**The author's decision: 0.5.7 stays as designed.** The app announces ArtCraft's release the moment it
ships, and the app always wins in the user's eyes: if the plugin says "up to date" while the app says
"update", it reads as a plugin bug. ArtCraft owns the apps, so OmarCraft follows the owner's release, as
packaged in the AUR, rather than a copy of it held back a day.

## Design

1. **One switch, off.** A new constant, `FOLLOW_APP_REPOS=0`, next to `APP_REPOS_RE`. With it at 0, a
   Craft app is an AUR app even when a repo ships its package name. With it at 1, everything behaves
   exactly as in 0.5.6: kind `repo`, Omarchy's version, `repo_update` with its checks. The 0.5.6 code is
   kept whole, and its tests run in both modes. It is a code constant, not a setting in the panel, so no
   new UI. Switching back is one line and a release.
2. **Who it covers.** Apps without a pinned kind (`KIND_OF`), today WordCraft and GridCraft, and any Craft
   app Omarchy adds to its repo later. Typesetter and Planify stay pinned to the Arch repos and update with
   the system, as now.
3. **Kind and version.** `kind_var` puts these apps in `aur` while the AUR has a build. If the AUR has
   none (the package removed there, or no version in the catalog), the app falls back to its repo, as in
   0.5.6, so a repo-only app is never stranded. The version shown and compared is the AUR's (the catalog
   column already carries it for these apps, format 2).
4. **Install.** `yay -S --noconfirm --needed -- aur/<pkg>` after `refuse_source_builds`, then the same
   check as `omarchy-pkg-aur-add` makes (`pacman -Q <pkg>`, without the prefix). `omarchy-pkg-aur-add` is
   not used for these apps: its own final check runs `pacman -Q aur/<pkg>`, which always fails, so it
   would install the app and still report an error (checked 2026-11-09). AUR apps no repo ships keep
   `omarchy-pkg-aur-add`.
5. **Update.** The existing package-exact update, with the prefix for these apps:
   `yay -S --noconfirm aur/<pkg>`. *Update all*, the menu and `omarcraft update` treat them like any AUR
   app.
6. **Moving the installed apps.** No separate step. A machine with Omarchy's WordCraft 0.16.0 sees
   `↑ 0.17.0` once the AUR has 0.17.0; Enter installs the AUR build over it (same name, so pacman replaces
   it in place; documents and settings untouched). Where Omarchy's build is as new as the AUR's, nothing
   changes until the next AUR release.
7. **Panel.** No new UI. The subtext of a not-yet-installed WordCraft or GridCraft no longer says *from
   Omarchy's repo*. The state's `repo` field stays empty for them.
8. **Cache format 5**, so the first read after the update checks at once and the badges appear without
   waiting six hours.
9. **README.** The section "The apps' own update prompts" is updated: OmarCraft takes the Craft apps from
   the AUR, which follows ArtCraft's releases within hours. The app's own button still cannot update a
   pacman install, so use OmarCraft. Plus one line on Omarchy's update possibly bringing Omarchy's build
   when it is the newer one.

## How each case behaves (switch off)

| Case | Panel | Action |
|---|---|---|
| Omarchy's build installed, AUR newer (today: WordCraft 0.16.0 / 0.17.0, GridCraft 0.17.0 / 0.18.0) | `↑ 0.17.0` | Enter: `yay -S aur/wordcraft-bin`, one package; the badge clears |
| AUR build installed, Omarchy's repo older | No badge | Omarchy's update leaves it (no downgrade) |
| AUR build installed, Omarchy's repo newer (or a higher pkgrel of the same version) | No badge (installed ≥ AUR) | Omarchy's update has already brought Omarchy's build; OmarCraft offers the AUR's next release when it is newer |
| Not installed | AUR's version, no repo subtext | `yay -S --needed aur/<pkg>` |
| AUR drops the package, a repo still ships it | Repo app, as in 0.5.6 | Omarchy's repo, `repo_update` |
| Source build (package `<id>`) | Source build | Never updated or removed by OmarCraft, as before |
| Typesetter, Planify | As in 0.5.6 | Omarchy's update |
| Switch on (`FOLLOW_APP_REPOS=1`) | As in 0.5.6 | As in 0.5.6 |

## Tests (offline, before the build is installed)

- Both modes for every 0.5.6 repo test (the 267 must still pass with the switch on).
- The `aur/` prefix on install, update and *Update all* for an app a repo ships; never on an AUR app no
  repo ships (`omarchy-pkg-aur-add` stays for those).
- The install's final check passes on the plain name.
- Fallback to the repo when the AUR has no version for the app.
- No badge when the installed build is newer than the AUR's (Omarchy's update brought it).
- Format 5 checks at once.
- Each new piece broken on purpose in a copy, and a test must fail each time (as in 0.5.4 to 0.5.6). The
  fake `pacman` must print `-Q` lines exactly as the real one does, which is the lesson from 0.5.3.
