# OmarCraft 0.6.7 plan

**Status: the author's go of 2026-11-25 ("implement and document A, then release 0.6.7 (instead of 0.6.0)").
0.6.7 is the release of everything since 0.5.8: the 0.5.9 build (`docs/v0.5.9-plan.md`, accepted on the
author's machine, rows 81–93) and quiet updates below. 0.5.9 is not released on its own: one marketplace review.**

## Why

The Craft apps announce a new version themselves, at start and in *Help › Check for Updates*, often before
the AUR has the build, and their own updater cannot replace a package pacman owns. On 2026-11-25 PdfCraft
offered 0.22.0 by itself while OmarCraft showed the same update (row 81). ArtCraft's real switch for managed
installs is on its way (storytold/craft-contrib#82, RFC-0082; craft-libs#2629, an off switch in the shared
updater, reviewed 2026-11-22; craft-libs#572, `CRAFT_UPDATE_STARTUP=0`), but none of it is merged or shipped.

## What the apps already read (checked 2026-11-25)

Every ArtCraft app reads the ArtCraft Launcher's version file, `ArtCraft/versions/versions.json` in the
per-user data folder (`$XDG_DATA_HOME` or `~/.local/share`), or the file `CRAFT_VERSIONS_FILE` names
(craft-libs `crates/update/src/pins.rs`, unchanged since 2026-10-30). An app the file lists with anything but
`Stable` follows that entry: no update prompt at start, and *Help › Check for Updates* says "{app} {version}
follows the version chosen in the launcher, so it does not update itself." An entry the app cannot read counts
as chosen elsewhere, never as stable, and the launcher writes such an entry back unchanged. On the author's
machine all 16 ArtCraft apps read it (`CRAFT_VERSIONS_FILE` in each binary); MailCraft (community, with an
updater of its own) does not, SolidCraft has no updater.

## The decision (the author, 2026-11-25: option A)

A command, no panel change: `omarcraft quiet-updates on|off|status`.

- **on** lists, in that file, each ArtCraft app (upstream group `suite`) installed as a package, with the
  entry `{"ManagedBy":"OmarCraft"}`, and records those ids in `~/.local/state/omarchy/omarcraft/quiet-updates`.
  An app the file already names (a launcher pin, nightlies, anything a newer launcher wrote) is left as it is
  and not recorded. Keys the file has besides `apps` are kept.
- **After every job** (install, update, removal) while it is on, the list follows what is installed: a new app
  is listed, OmarCraft's entry for a removed app goes. It never changes how a job ended.
- **off** takes out exactly the entries with OmarCraft's mark; a file left with nothing else goes (no file
  means every app follows stable releases, as an empty one does).
- **status** names the apps listed.
- A file that is not the launcher's JSON (or over 1 MB) is never touched; `on` then stays off and says why.
- Written in one step (a temporary file, then a rename), as the launcher does, so an app never reads half a
  file. The file `CRAFT_VERSIONS_FILE` names (an absolute path) is the one used, as the apps do.
- Off by default: the first plan's rule, nothing written outside OmarCraft's own folders unless asked.

Not in it: a panel switch (option B, would need a canvas round), anything for MailCraft, and the RFC's
machine-wide policy file (`/etc/<id>/policy.json`, root's: OmarCraft never elevates; that is for Omarchy or the
packages). When ArtCraft's switch ships, OmarCraft moves to it and drops this.

## Tests

16 offline tests: nothing written by default; on lists only installed ArtCraft apps (no community app, no tool
beyond ArtCraft); recorded as its own; status; idempotent; a launcher pin, another app's entry and unknown keys
kept; after an install and after a removal; a damaged file left alone, never failing a job, refused by on;
off takes out its own entries and removes a file left empty, leaves what it did not write; CRAFT_VERSIONS_FILE.
356 offline tests and 72 panel-logic tests in all.

On the author's machine: turned on, the file checked, one app started and its log read for "follows the
launcher's choice" (rows 94–98 in `v1-acceptance.md`).
