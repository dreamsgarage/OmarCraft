# OmarCraft 0.5.1 plan

**Status: proposed 2026-10-23; decided and released 2026-10-23 (the author: "go with 0.5.1").**
Built on the branch `v0.5.1`.
0.5.0 (commit acdb8d4) is awaiting marketplace verification in omacom/omarchy-plugin-marketplace#12723;
0.5.1 replaces that request with a new one at its own commit.

## Goal

A clean, honest 0.5.x for the marketplace review: fix what 0.5.0 got wrong, and decide whether Vikunja
stays, because its desktop app cannot sign in on a stock Omarchy install.

## Findings (2026-10-23)

### Vikunja's desktop app cannot sign in

Vikunja's desktop app (2.7.x) signs in through the browser: *Login* opens the server's authorize page in
the default browser, which approves the app and hands a one-time code back through a
`vikunja-desktop://callback` link. The app keeps the matching PKCE verifier in memory and redeems the code
at `/api/v2/oauth/token`.

- Since the 2.7.1 update the app has never signed in. The server recorded four approvals (15:19, 15:19,
  15:37, 15:53), each a ten-minute code for `vikunja-desktop://callback`; none was ever redeemed. The only
  session in the database was the browser's. The app sat on *Login · Waiting for authentication…*.
- The local half of the hand-off works: a fake callback sent with `xdg-open` reached the running app
  through OmarCraft's desktop entry, launch script and session, and the app tried to redeem it (the
  server answered 400, as it should for a fake code).
- So the hand-off stops in the browser. The approval page redirects to the link on its own as soon as it
  loads (no click of its own); Chromium opens a link to another app only after its *Open xdg-open?*
  prompt, and can refuse it when no click started the page. Chromium holds no "always allow" for
  this link. On 2026-10-18 (2.7.0) the same hand-off worked once: the code was redeemed 14 s after the
  approval, the time it takes to answer that prompt.
- Why a new sign-in was needed at all: the app's 2026-10-18 session no longer existed on 2026-10-23
  (Vikunja's default session lasts 3 days, 30 with *remember me*), and 2.7.1 also drops stored tokens
  when the server address changes. Every lapse means the browser hand-off again.
- One more 2.7.1 fault seen today: a sign-in failed once with *database is locked* (SQLite), when two
  requests wrote at the same moment.

### Other 0.5.0 faults

- A job whose terminal is closed mid-job was recorded as a success (exit 0): bash ran the EXIT trap with
  the status of the last finished step. Seen live: a removal cut off at the password prompt read as done
  while both packages stayed installed. **Fixed on this branch** (7529dce): hangup, Ctrl+C and kill exit
  130, recorded as interrupted.
- README *Safety* contradicts 0.5.0: it says only `<id>-bin` names reach a package command and installs go
  through `omarchy-pkg-aur-add` (Typesetter is `typesetter` through `omarchy-pkg-add`), and "nothing under
  `~/.config` without the opt-in commands" (every Vikunja launch writes the tray Hide list in
  `~/.config/omarchy/shell.json`); its file list leaves out Vikunja's data folder and desktop entry.
  `docs/marketplace-submission.md` repeats it.
- `preview.png` still shows the 0.2.0 panel (*12 OF 14 INSTALLED*, no Typesetter, no Vikunja).
- The GitHub description still reads as an ArtCraft-only plugin.

## Clean-install test (2026-10-23)

The author asked for a clean install before deciding. Through the panel's own jobs:

| Time | Step | Result |
|---|---|---|
| 16:22 | Remove Vikunja (job) | App quit and server stopped first; both packages dropped; OmarCraft's desktop entry gone |
| 16:23 | Move the data folder and the app's profile aside | `~/.local/share/omarcraft/vikunja.backup-20261023-1623`, `~/.config/vikunja-desktop.backup-20261023-1623` |
| 16:24 | Install Vikunja (job) | Both packages installed; the app opened on a fresh profile with a new server config and an empty database |
| 16:24–16:26 | Browser tab left open from before | Kept calling the new server with the old server's token (401) until it logged itself out |
| 16:26 | Log in from the browser | Refused twice: a clean install has no account |
| 16:27, 16:28 | The app's window closed | Its server stopped with it, by design; the registration then tried in the browser failed with *Failed to fetch* |

No registration and no sign-in reached the server after the reinstall, and the desktop app never signed
in. A clean state changes nothing: the sign-in needs the browser, the browser needs the server, and the
server lives only while a window that cannot do anything yet stays open.

## Decision (the author, 2026-10-23)

**A: drop Vikunja in 0.5.1.** The author asked for keep-or-drop after the clean install; this plan
recommends A, the branch implements it, and the author approved it with the release. B (Vikunja as a web app: server plus an Omarchy web-app
window, normal web sign-in) is a new design and belongs in its own plan, next to a native, serverless
tasks app (Errands or Planify, both in the Arch repos), if the tasks gap is to be filled again.

| | Option | What it takes | Effect |
|---|---|---|---|
| **A** | **Drop Vikunja** in 0.5.1 | Remove the tile, server, session, tray and entry code; clean up what 0.5.0 left (below) | Notes = Memospot; no server, no Electron client, no write to `shell.json`; Safety holds without caveats |
| B | Keep Vikunja as a web app | Server only (`vikunja-bin`), opened in an Omarchy web-app window; normal web sign-in with *remember me* | No desktop client, no hand-off, no tray icon; a new launch flow, its own plan and acceptance |
| C | Keep the desktop client as is | Document the *Open xdg-open* prompt and "always allow" | Sign-in still depends on the browser and a window kept open, and repeats whenever a session lapses |

## Design

- **Removed:** the Vikunja tile and catalog entry, its two packages, the local server (config, start,
  stop, session, window watcher), the tray handling (Hide-list writes in `~/.config/omarchy/shell.json`,
  the bus wait, the reload resync in `Service.qml`), the user desktop entry and launcher, the tile's server
  dot and the `serverRunning` field of `state`. About 300 lines of `bin/omarcraft` and 50 tests.
- **Kept:** the generic support for repo tools and for tools with several packages (Typesetter uses the
  first), and the install/launch/update/remove paths of the fifteen tools, unchanged.
- **What 0.5.0 left** (`legacy_vikunja_cleanup`, run by every `state` read and by 0.5.0's old commands):
  if `~/.local/share/applications/vikunja-desktop.desktop` carries `X-OmarCraft=true`, delete it and the
  `launch` script next to the data, and post one notification naming the data folder and the removal
  command. A stale server pid file is deleted; a live one is left. Not touched: the packages, the data
  folder, a running server, the tray Hide list entry (the tray's own settings show it again), and any
  entry the user wrote. Without this, 0.5.0's launcher entry would call a command 0.5.1 no longer has.
- **Fixed on the way:** an interrupted job is recorded as interrupted (7529dce); README *Safety*, the HTML
  README and the marketplace notes match the code; `omarcraft --help` prints its last line.

## Risks

- A 0.5.0 user who keeps Vikunja installed loses the server OmarCraft ran for it; the notification and the
  README say where the data is and how to remove the app.
- Vikunja's icon stays hidden in the tray for such a user until they show it from the tray's settings.
